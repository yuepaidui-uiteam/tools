# B 站下载器 GitHub Pages 与一键本机安装器设计

## 目标与成功标准

将 B 站下载页面作为 GitHub Pages 静态页面发布。用户无需下载包含其他工具页面的整个仓库压缩包；首次通过一个 Windows 安装器安装 Python、FFmpeg，并自动准备下载器所需的少量本机服务文件。之后用户从 GitHub Pages 页面输入链接和下载，服务只在自己的电脑上运行。

成功标准：

- 安装说明不再引导下载整站 ZIP、复制命令或手工配置 PATH。
- 用户只需下载并运行一个安装器；安装器按需安装 Python 和 FFmpeg，准备本机依赖与服务文件，并创建易于再次启动的入口。
- 用户日常操作仍在 GitHub Pages 页面完成；本机服务关闭时，页面能说明如何启动，不展示要求用户手动访问的 localhost 地址。
- 服务只监听 `127.0.0.1`，不开放给局域网或公网；安装器不下载其他站内工具页面。
- 明确提示 winget/Windows 可能要求用户确认；不尝试绕过系统安全或安装确认。

## 用户流程

1. 用户从 GitHub Pages 打开 B 站下载页面。
2. 首次使用，点“下载并安装”获取独立安装器；浏览器下载后由用户确认运行。安装器检查 winget，安装 Python 与 FFmpeg，下载 B 站服务所需的文件到用户目录，为 Python 依赖创建独立虚拟环境，并生成“启动 B 站下载器”入口。
3. 安装结束后启动本机服务并提示用户回到 GitHub 页面；若浏览器页面没有自动恢复，用户刷新当前页。
4. 后续使用时，用户先从启动入口运行本机服务，再在 GitHub 页面粘贴链接、下载视频。停止服务只需关闭其命令窗口。

## 方案与取舍

采用“静态 GitHub Pages + 独立 Windows 安装器 + loopback Flask 服务”。

- 页面仍为静态站点，不承担 Python/FFmpeg 安装，也不代理视频流。
- 单文件 `install.bat` 通过 HTTPS 从 `yuepaidui-uiteam/tools` 仓库 `main` 分支分别下载 `app.py`、`requirements.txt`、`templates/index.html`；不下载图片工具、首页等仓库其他内容。后端文件与页面随 `main` 分支更新，重新运行安装器可更新本机文件。
- 服务继续复用现有 Flask/yt-dlp 实现，绑定 `127.0.0.1:5000`。页面在 iframe 内加载本机服务；视频解析、下载及保存仍由本机完成。
- 不采用在线下载后端，以避免新增服务器、存储、带宽、隐私与运维成本；也不采用整个仓库 ZIP，以满足用户不想下载其他网页的要求。

## 安装器职责与安全边界

- 仅面向 Windows 10/11；检查 winget 是否可用，并用当前既定的 winget 包标识安装 Python 与 FFmpeg。
- 所需文件安装到当前用户可写目录；Python 项目依赖放在独立虚拟环境，不污染系统 Python。
- 下载地址使用仓库的 HTTPS 原始文件地址；安装器只取下载器白名单文件，不执行远端任意命令或整个仓库中的其他页面。
- 安装器检查每个步骤退出码、下载结果及启动所需组件；失败时用中文指出失败步骤和回到说明页的方式，不留下“安装成功”的误导状态。
- 不绕过 UAC、winget 确认、浏览器下载提示或 PowerShell/Windows 安全策略。任何系统确认都由用户操作。
- Flask 保持关闭 debug 模式、只绑定 loopback；不添加通配 CORS，不将下载服务暴露到网络接口。
- 首次完成安装后创建本机启动入口；它只启动本地服务，不在后台静默常驻。用户可关闭窗口停止。

## 页面内容调整

- 移除“下载工具包 ZIP”、PowerShell 手动复制命令及手工 PATH 配置说明。
- 改为一个主要操作：“下载 Windows 一键安装器”，补充安装器安装 Python、FFmpeg 并自动准备本机下载服务。
- 用简短步骤说明首次安装、确认系统提示、回到本页使用，以及下次如何启动服务。
- 本机服务未运行时，在嵌入区域显示友好提示；保留本机地址作为 iframe 的内部实现，不把它作为可见导航或要求用户手动输入的地址。
- 说明该网页可公开访问，但视频处理仍发生在本机；网络不可用、没有 winget、安装失败或服务未启动时，给出明确的恢复路径。

## 组件与预期文件

- `bilibili-downloader.html`：GitHub Pages 上的工具页与安装引导。
- `bilibili-downloader/install.bat`：唯一需从网页下载并运行的安装器；安装依赖、获取最小服务文件、创建本机启动入口。
- `bilibili-downloader/app.py`、`requirements.txt`、`templates/index.html`：安装器取用的本机服务文件。
- `bilibili-downloader/run.bat`：供安装后启动入口调用，负责启动本地 Flask 服务。

实施前需要核对仓库公开地址、GitHub Pages 的准确页面来源，以及 winget 包标识在目标 Windows 环境中的安装结果；这些信息会在实施计划和验证中记录。

## 错误处理与恢复

- winget 缺失：停止自动安装，显示安装 App Installer/winget 的简短官方引导链接。
- Python 或 FFmpeg 安装失败：保留错误码和失败组件名称，提示用户修复后重运行安装器。
- 文件下载失败：不启动不完整服务；提示检查网络并重试，文件下载到临时名后校验成功再替换。
- Python 依赖安装失败：显示 pip 错误并允许重试，不影响系统 Python。
- 本机服务未启动或端口不可用：页面告知运行本机“启动 B 站下载器”入口并刷新；启动器发现端口被占用时给出清晰提示，不关闭其他进程。

## 验收与测试

- 页面内容检查：没有整站 ZIP 引导、手工粘贴命令或要求手工修改 PATH 的步骤；入口下载目标是独立安装器。
- 安装器静态检查：下载白名单、TLS 地址、错误码处理、幂等重跑、用户目录写入、loopback 启动约束；确认不含删除用户文件或终止不相关进程的操作。
- 自动化测试：安装流程各步骤失败时能停止并显示正确错误；已安装依赖时可重复运行；下载的文件集合恰为服务所需文件。
- 本机集成测试：干净目录安装、启动入口、服务状态、嵌入页面可用和关闭服务后的提示。
- 浏览器测试：用 GitHub Pages 的真实 HTTPS 来源验证 iframe 在 Edge 中可载入 localhost 服务；在桌面与窄屏检查布局、控制台错误及输入流程。
- 若未将变更发布到 GitHub Pages，则真实 HTTPS 来源验证记为未完成，不以本地 HTTP 预览代替。

## 不在本次范围

- 代替用户安装或绕过 Windows 确认。
- 为多人提供云端解析/下载服务。
- 修改 B 站下载格式、清晰度策略或账号登录能力。
- 自动推送/发布到 GitHub，除非用户另行明确要求。
